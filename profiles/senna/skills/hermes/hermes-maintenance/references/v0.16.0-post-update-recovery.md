# v0.16.0 Post-Update Recovery (2026-06-08)

## What Broke

After `hermes update` (v0.15.1 → v0.16.0, 290 commits):

1. **Senna profile CLI wrapper** — pointed to non-existent path `profiles/senna/hermes-agent/venv/bin/hermes`
2. **Mnemosyne wiped** — `mnemosyne-memory`, `fastembed`, `sqlite-vec` all gone from venv
3. **iknowkungfu-mcp wiped** — binary gone from venv
4. **rtk-hermes wiped** — `rtk-rewrite` plugin gone from venv
5. **7 cron jobs broken** — model routing bug sent `deepseek-v4-pro` to xiaomi endpoint
6. **1 cron job broken** — `ue5-playlist-transcripts` had `model: null` falling back to deepseek

## Recovery Steps (in order)

### 1. Fix profile wrapper
```bash
cat > ~/.hermes/profiles/senna/home/.local/bin/hermes << 'EOF'
#!/usr/bin/env bash
unset PYTHONPATH
unset PYTHONHOME
exec "~/.hermes/hermes-agent/venv/bin/hermes" "$@"
EOF
chmod +x ~/.hermes/profiles/senna/home/.local/bin/hermes
```

### 2. Reinstall mnemosyne (Intel-safe)
```bash
cd ~/.hermes/hermes-agent && ./venv/bin/pip install mnemosyne-memory fastembed sqlite-vec
~/.hermes/hermes-agent/venv/bin/python3 -m mnemosyne.install
```
Verify: `~/.hermes/hermes-agent/venv/bin/python3 -c "from mnemosyne.core.memory import Mnemosyne; ..."`

### 3. Reinstall iknowkungfu
```bash
cd ~/.hermes/hermes-agent && ./venv/bin/pip install iknowkungfu
```
Verify: `ls ~/.hermes/hermes-agent/venv/bin/iknowkungfu-mcp`

### 4. Reinstall rtk-hermes
```bash
cd ~/.hermes/hermes-agent && ./venv/bin/pip install rtk-hermes
```
Verify: `~/.hermes/hermes-agent/venv/bin/pip show rtk-hermes`

### 5. Fix cron jobs (model field MUST be string)
```python
import json
path = "~/.hermes/profiles/senna/cron/jobs.json"
with open(path) as f:
    data = json.load(f)
for job in data['jobs']:
    err = str(job.get('last_error', ''))
    if 'Not supported model' in err or job.get('model') is None:
        job['model'] = 'mimo-v2.5-pro'  # STRING not dict!
with open(path, 'w') as f:
    json.dump(data, f, indent=2, default=str)
```

### 6. Restart gateway
```bash
hermes gateway restart --profile senna
```

### 7. Re-trigger failed cron jobs
```bash
# Check which failed
hermes cron list 2>&1 | grep error

# Re-trigger each
hermes cron run <job_id>

# Wait 60-90s, check again. Some may need a second trigger
# (scheduler cached pre-fix config).
```

## Pitfalls Discovered

- **Model field format**: `jobs.json` `model` field MUST be a plain string (`"mimo-v2.5-pro"`), NOT a dict (`{'provider': 'xiaomi', 'model': 'mimo-v2.5-pro'}`). Dict causes `'dict' object has no attribute 'lower'`.
- **hermes cron edit has no --model flag**: Must edit jobs.json directly.
- **Double-trigger needed**: Scheduler caches job config. After fixing jobs.json, first re-trigger may still use old config. Trigger once, wait 60s, check, trigger again if needed.
- **Mnemosyne MCP vs native plugin**: Mnemosyne ships `mnemosyne mcp` for external clients. For Hermes, the native `hermes_memory_provider` plugin is superior (lifecycle hooks). Do NOT add mnemosyne to mcp_servers.
- **Intel Mac mnemosyne install**: Never use `mnemosyne-memory[all]` — it builds llama-cpp-python from source which hangs. Always install `mnemosyne-memory fastembed sqlite-vec` individually.
