# Vault Revamp (kanban worker)

## Orientation

Always read `kanban_show()` first. For a revamp task, the two trustworthy inputs are:
- `_UE5_8_Convention_Standard.md`
- `Research/_incoming/curation_report.md section 2` for your category

## Work discipline

- Do not modify files outside the task workspace unless the body explicitly requires it.
- If saving every request costs a turn, limit automation to once after all category notes are annotated.
- Cease editing the next note only after successful completion of the active one.

## Classification choice

- Prefer `status: current` with `historical_notes` when no deprecated symbols are present.
- Use `status: legacy` / `deprecated` only when the standard or curation report explicitly identifies removed/deprecated APIs.
- Do not guess deprecated artifacts from memory.
